PROBLEM

재고 확인과 입력 공간의 분리

02

ANALYSIS

입력값 · 상품 정보 · 실재고의 역할 분해

현장에서 바로 입력하도록 모바일로 업무를 옮기면서, 입력값·상품 정보·실제 재고의 역할과 반영 기준을 분리했다.

01

판단해야 했던 문제 → 결정한 방향

고려해야 했던 문제

결정

현장에서 입력한 값을 언제 실제 재고에 반영할 것인가?

모바일 입력과 실제 재고 반영을 분리한다.

상품 정보와 실재고를 하나의 흐름으로 관리할 것인가?

상품 정보와 실재고를 별도 흐름으로 분리한다.

여러 건의 제출값을 PC에서 어떻게 처리할 것인가?

PC에서 확인 후 필요한 건을 선택해 반영하는 구조로 한다.

입력한 실재고를 기존 전산 재고와 어떻게 반영할 것인가?

현장에서 확인한 수량을 기준으로 실제 재고를 반영한다.

여러 약사가 같은 상품을 중복 입력하면 어떻게 할 것인가?

중복 제출을 구분하고 최종 반영값을 선택할 수 있도록 한다.

현장 입력은 모바일로 단순화하고, 실제 재고 반영과 상품 정보 관리는 각각 별도의 기준으로 분리했다.

03

SOLUTION

입력과 반영을 나눈 데이터 흐름 설계

현장에서 입력한 데이터와 실제 재고를 분리하고, 약사앱 → 서버 → PC → 약국 재고로 이어지는 흐름을 설계했다.

앱은 입력·제출, PC는 확인·반영, 슈퍼어드민은 상품 마스터를 관리한다.

01

상품·실재고 데이터 흐름

  1. 1

    약사앱

    바코드 스캔 → 상품 등록 / 실재고 입력 → 제출

    →
  2. 2

    제출 데이터

    상품 정보 / 진열·창고 수량 → 반영 전 데이터로 저장

    →
  3. 3

    PC 클라이언트

    제출 내용 확인 → 필요한 건 선택 → 실제 재고 반영

    →
  4. 4

    약국 재고

    PC에서 반영한 총 수량을 실제 전산 재고로 적용

02

Role Separation · 플랫폼별 역할

슈퍼어드민에서 실재고를 관리하는 것이 아니다. 실재고는 약국 운영 데이터이며 PC 클라이언트에서 최종 반영된다.

03

상품 정보와 실재고를 분리

데이터 성격과 책임 주체가 다르기 때문에 흐름을 분리

05

정책

입력값의 오류와 데이터 혼선을 줄이기 위해 수량·상태·반영 기준을 각각 했다.

06

예외 상황

중복 제출·네트워크 오류·재고 차이 등 예외 상황에서도 입력값과 실제 재고의 기준이 섞이지 않도록 처리 구조를 분리했다.

여러 약사가 같은 상품을 제출+
바코드로 묶어 1건만 선택 — 최신 기본, 원본 보존
제출 중 네트워크가 끊김+
전체 실패 처리, 제출 목록 유지 — 다시 시도
앱과 PC의 재고 차이+
스냅샷과 현재 재고의 시간 차이 — 최종 재고는 반영 시점 총 수량
기존 전산 재고와 입력값이 동일+
보정 사유 입력란 숨김 — 쓴 사유는 세션 보관
