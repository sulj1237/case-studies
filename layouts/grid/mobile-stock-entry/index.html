OVERVIEW

현장에서 입력한 값이 언제부터 실제 재고가 되는지 정의한다. 휴대폰은 입력, PC는 확인과 반영을 맡는다

항목내용
기간2026.06 ~
담당데이터 상태 모델 · 앱·PC 역할 분리 · 제출·반영 정책 · 화면 정의
진행설계 진행 중 · 미출시

핵심 — 보낸 값과 약국 재고를 다른 상태로 두고, 경계는 PC의 반영이다

PROBLEM · 현장과 PC 분리, 데이터 상태 불명확

확인은 진열대와 창고, 입력은 PC다. 왕복과 재입력이 반복되고 입력값의 반영 시점 기준이 없던 상태다

근거 — 기존 실재고 업무 흐름 관찰. 확인 장소와 입력 장소가 분리돼 기억 · 메모 · 이동 · 재입력이 반복된다. 그래서 입력한 값이 언제 실제 재고가 되는지 어느 화면에도 적혀 있지 않는다

입력 이원화

확인은 현장, 입력은 PC

진열대·창고에서 세고 PC로 이동해 다시 입력한다

상태 불명확

반영 시점 기준 없음

즉시 반영인지 PC 확인 후 반영인지 정해진 바 없다

중복 제출

같은 상품 여러 건

여러 약사·기기가 제출할 때 어느 값이 기준인지 불명확하다

시간 차이

조회 시점과 반영 시점

앱에서 본 재고와 PC 반영 시점 재고가 달라진다

DECISION · 무엇을 골랐나

화면보다. 먼저 값의 상태를 정의한다. 기능 단위로 묶었던 흐름을 데이터 성격 단위로 다시 나눈다

01

PC 반영 후에 재고

현장 입력은 보낸 값, 실제 재고는 PC에서 반영한 순간부터다. 즉시 반영은 되돌릴 방법이 없어 선택하지 않는다

02

상품 정보와 실재고 분리

마스터 갱신과 수량 입력은 성격이 달라 흐름을 나눈다. 상품 수정 화면에서는 수량을 받지 않는다

03

덮어쓰기 · 중복은 묶어서 1건

실사 결과가 최종값이므로 더하기 대신 덮어쓴다. 같은 바코드는 묶어 보여주고 최신 제출을 기본 선택한다

HOW · 어떻게 만들었나

값은 입력 → 제출 → 확인 → 반영을 거쳐 재고가 되고, 상태가 바뀌는 지점마다 기록한다

상태의미실제 재고
반영전제출됨 · PC 미처리변화 없음
반영완료총 수량이 전산 재고에 반영총 수량으로 변경
반영반려반영 없이 처리 종료변화 없음
반영실패시스템 오류 · 재시도 대상변화 없음
규칙내용
총 수량진열 + 창고 자동 합산
미입력과 0- 입력 안 함 · 0 재고 없음
보정 사유전산과 총 수량이 다를 때만 노출 · 30자
앱 기준 스냅샷반영 기록 수량은 제출 시점 전산 재고 기준

RESULT · 무엇이 정해졌나

현장에서 센 값이 언제 재고가 되는지 한 곳에서 정해진다. 휴대폰은 입력, PC는 반영으로 갈랐다

기존설계 후
입력하는 곳PC 앞상품이 있는 현장
실제 재고가 되는 시점입력 즉시PC에서 반영한 순간
최종 값을 정하는 곳입력한 사람PC 한 곳
처리 결과건건이 처리하고 끝4가지 상태와 반영 기록

다음 고도화 — 반영 권한 범위와 부분 실패 처리를 더한다. 제출에서 반영까지 걸린 시간과 반영반려 비율을 보고 상태 모델을 조정한다
