현장과 PC 분리, 데이터 상태 불명확

확인은 현장(진열대·창고), 입력은 PC. 약사가 기억·메모·이동·재입력을 반복하며, 입력한 값이 언제 실제 재고가 되는지 기준이 없었습니다.

입력 이원화

확인은 현장, 입력은 PC

진열대·창고에서 확인하고 PC로 이동해 재입력하는 왕복 반복

상태 불명확

입력값의 반영 시점 모름

현장 입력값이 즉시 반영되는지, PC 확인 후 반영되는지 기준 없음

동시 입력

여러 약사·기기 중복 제출

같은 상품을 여러 사람이 제출할 때 어느 값이 맞는지 기준 없음

재고 불일치

조회 시점과 반영 시점 차이

앱에서 본 재고와 PC 반영 시점 재고가 달라지는 시간 차이 발생

입력은 현장, 반영은 PC

현장 입력값을 바로 재고에 넣지 않고, PC 확인 후 반영하는 구조로 데이터 상태를 정의했습니다.

판단내용
PC 반영 확정입력은 앱, 확정은 PC. 최종 재고 확정 지점을 PC '반영' 하나로 둠
상품·재고 흐름 분리상품 정보(마스터)와 실재고를 별도 흐름으로. 반영 방식·책임 주체 다름
선택 반영건별 승인/반려 대신 '반영할 건 선택 → 반영'으로 단순화. 미체크는 자동 반려
실재고 덮어쓰기진열+창고 총 수량으로 덮어쓰기. 방식 선택 모달 제거, 동일 입력 = 동일 결과
중복 제출 묶음 처리동일 바코드 묶고 1건 선택. 최신 기본, 원본 모두 보존

데이터 상태 분리 구조

보낸 값(반영전)과 실제 재고(반영후)를 분리하고, PC 반영 시점에만 재고가 확정됩니다.

구성내용
데이터 상태 4종반영전 → 반영완료 / 반영반려 / 반영실패
상품 흐름마스터 흐름(본사 원본 · PC 선택 반영) / 재고 흐름(PC 덮어쓰기 반영) 분리
역할 분리앱=입력·제출 / PC=확인·반영 / 본사=마스터 관리
중복 처리동일 바코드 묶음 → 최신 1건 선택 · 원본 모두 보존
