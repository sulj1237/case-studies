Overview

약국이 약국 단위로 독립 운영하는 포인트 시스템을 신규 설계했다. 고객은 약국별로 별도 포인트를 보유한다.

적립률·사용 조건을 약국이 정하되, 본사가 시스템에서 통제할 수 있는 범위를 함께 설계해야 했다.

적용 플랫폼

다섯 개 채널이 하나의 포인트 원장을 공유한다.

Context

케어팜 플랫폼에는 약국이 단골 고객을 관리할 수 있는 수단이 없었다. 약국은 재방문 고객을 알아볼 방법도, 재방문을 유도할 수단도 갖고 있지 않았다.

포인트를 도입하려면 두 가지가 동시에 성립해야 했다.

조건 1

다섯 채널에서 일관되게 동작

고객은 앱에서 조회하고 키오스크에서 가입하고 POS에서 쓴다. 약국은 어드민에서 보고 본사는 슈퍼어드민에서 감사한다. 한 채널에서만 성립하는 규칙은 나머지 네 곳에서 깨진다.

조건 2

약사법 제약 안에 있을 것

약국 포인트는 약사법상 환자 유인행위 리스크를 안고 있다. 적립률을 약국이 자유롭게 정하게 두면 그 리스크가 플랫폼으로 넘어온다.

Problem

문제를 세 층으로 나눠 정의했다. 셋을 섞으면 해법이 어긋난다.

비즈니스 문제

고객 관계를 쌓을 도구가 없다

약국 입장에서 케어팜은 결제·조제를 처리하는 도구일 뿐이었다.

사용자 문제 · 고객

자주 가도 쌓이는 게 없다

다른 약국을 가도 잃는 것이 없다.

사용자 문제 · 약국 직원

단골인지 알 방법이 없다

안다 해도 줄 수 있는 것이 없다.

구조 문제

금전적 가치를 갖는 원장

다섯 채널이 같은 잔액을 읽고 쓴다. 이쪽이 실제 설계 난이도였다.

구조 문제를 구체적으로

어느 채널에서든 이중 적립·이중 차감이 일어나면 그대로 손실이 된다. 결제 취소·환불이 들어오면 이미 적립된 포인트를 회수하고 이미 쓴 포인트를 복구해야 한다.

동시에 약사법 리스크가 걸려 있다. 조제약·의약품에 포인트를 붙이는 순간 환자 유인행위 소지가 생긴다. 약국별 자율성을 넓힐수록 리스크는 커지고, 좁힐수록 기능의 의미가 사라진다.

법률 · 규제

약사법 — 환자 유인행위

자유 적립률 설정에 리스크가 있다. 조제약은 적립·사용 제한이 필요하고, 일반의약품은 제한 또는 적립만 허용을 검토한다. 의약외품·비의약품은 허용 가능성이 높다.

개인정보

수집과 동의 이력 관리

키오스크 가입 시 전화번호·생년월일 8자리·성별을 수집한다. 약국별 약관 고지, 정책·약관 변경 이력, 제3자 제공 동의 이력을 남겨야 한다.

책임 구조

운영 책임은 약국에

약관 고지 책임도 약국에 있다. 슈퍼어드민 초기 범위에서 직접 부채·잔액 관리를 제외하고, 마이너스 포인트는 실제 부채로 관리하지 않는다.

Decision

자료에는 결론만 남아 있어, 각 결정을 대안·이유·포기한 것으로 되짚어 정리했다.

D1

포인트를 약국 단위로 독립 운영한다

대안

케어팜 통합 포인트 — 어느 약국에서 쌓든 어디서나 쓸 수 있는 구조

선택

약국별 독립 원장. 약국 간 합산·이동 불가.

이유

통합 포인트로 가면 포인트의 운영 주체가 케어팜이 된다. 그 순간 케어팜이 포인트 부채를 지고, 약사법상 유인행위 주체도 케어팜이 된다. 약국별로 나누면 각 약국이 자기 고객에게 자기 기준으로 운영하는 구조가 되고, 플랫폼은 원장과 통제 수단만 제공한다.

포기한 것

고객 관점의 편의. 여러 약국을 쓰는 고객은 포인트가 흩어진다. 단골약국 관리라는 목적에는 부합하지만, 범용 적립 서비스로서의 매력은 낮다.

D2

케어팜의 역할을 시스템 제공자로 한정한다

대안

본사가 포인트를 직접 운영·정산하고 약국은 정책만 선택

선택

운영 주체는 약국, 케어팜은 원장·정책 템플릿·모니터링만 제공. 슈퍼어드민 초기 범위에서 직접 부채·잔액 관리 기능을 제외했고, 고객 포인트 임의 조정도 제한적으로만 열었다.

이유

슈퍼어드민에 조정 권한을 열어두면 CS 요청이 전부 본사로 몰린다. 운영 부담보다 큰 문제는 책임 범위다. 본사가 잔액을 조정할 수 있으면 포인트 분쟁의 최종 책임자가 본사가 된다.

포기한 것

본사의 직접 개입 수단. 약국이 잘못 운영해도 즉시 바로잡을 수 없고, 모니터링과 액션 로그로 사후 확인하는 방식이 된다.

D3

포인트 사용 인증을 고객앱 바코드로 고정한다

대안

PIN 인증 · 전화번호 확인 · QR

선택

고객앱 바코드 단일 수단. QR을 제거하고 PIN 인증은 범위에서 뺐다.

이유

포인트 사용은 금전적 차감이라 본인 확인이 필요하다. 전화번호만으로는 타인이 남의 포인트를 쓸 수 있고, PIN은 약국 현장에서 직원 앞에 입력해야 해 결제 시간이 늘고 노출 위험이 있다. 앱 바코드는 앱 로그인 상태 자체가 인증을 대신하며 스캔 한 번으로 끝난다.

포기한 것

앱 미설치 회원은 포인트를 쓸 수 없다. 전화번호 회원은 적립만 가능하다. 이 결정이 남긴 사각지대는 후속 프로젝트에서 별도 경로로 해결했다.

D4

적립 기준을 실제 결제 잔액으로 한다

대안

결제금액 전액 기준

선택

결제금액에서 사용 포인트를 뺀 실결제액 기준. 거래번호로 중복 적립을 차단.

이유

전액 기준이면 포인트를 쓸수록 다시 적립돼 원장이 팽창한다. 약국이 부담하는 실제 매출과 적립액이 어긋나는 구조는 오래 갈 수 없다.

D5

1차 범위에서 부분 취소를 지원하지 않는다

대안

부분 취소 시 사용·적립 포인트를 비율로 안분

선택

일괄 취소만 지원.

이유

부분 취소는 라운딩 규칙(올림·내림)과 차감 우선순위가 함께 확정돼야 성립한다. 회계 기준이 정해지지 않은 상태에서 구현하면 원장 정합성이 깨진다.

포기한 것

부분 환불이 잦은 약국의 현장 편의. 해당 케이스는 전체 취소 후 재결제로 처리된다.

UX & System

정책을 채널별 역할로 나눠 배치했다. 각 채널은 그 자리에서만 할 수 있는 일을 맡는다.

키오스크

가입의 진입점

회원가입과 약관 동의를 여기 뒀다. 고객이 대기 중 스스로 처리할 수 있고, 시간이 걸리는 절차를 결제 카운터에서 떼어내야 직원 응대가 막히지 않는다. 조회는 전화번호 뒤 4자리 기준.

고객앱

조회와 인증

약국별 포인트를 카드로 보여주고 사용 시 바코드를 제시한다. 적립·사용·취소·수동조정·소멸 이력을 거래 일시·약국명·변동값까지 확인한다. 만료 14일 전 안내.

POS Client (POS)

처리

고객 조회, 실결제액 기준 적립, 바코드 인증 후 차감, 취소·환불 시 복구·회수. 최소·최대 사용 포인트를 검증하고 거래번호로 중복 적립을 막는다.

약국 어드민

운영

고객별·거래별 이력 조회, 수동 조정(사유·이력 필수), 거래 유형별 필터, 상세 Drawer에서 원거래·조정 사유·변경 전후 포인트 확인.

슈퍼어드민

감사

직접 운영하지 않는다. 약국별 운영 현황, 거래·수동조정 이력, 액션 로그 조회와 카테고리별 허용 여부·공통 약관 템플릿 관리에 한정.

Edge Cases

원장을 다루는 기능이라 예외 처리가 정책의 일부다. 각 항목을 열면 그렇게 정한 근거가 나온다.

통신 실패로 적립 요청이 재전송됨+
거래번호 기준으로 중복 적립을 차단한다. 재시도는 정상 동작이므로 요청 단위가 아니라 거래 단위로 판정해야 한다.
결제 취소 시점에 사용 포인트가 이미 만료+
복원되지 않을 수 있다. 만료는 시간 기준으로 이미 확정된 상태이기 때문이다.
취소했으나 적립분을 회수할 잔액이 부족+
자동 조정 포인트로 표기한다 (표기 방식 검토 중). 잔액을 음수로 두지 않기 위함이다.
잔액이 음수가 되는 상황+
실제 부채로 관리하지 않는다. 케어팜은 시스템 제공자이며 부채 주체가 아니다.
동일 전화번호 뒤 4자리 회원이 복수+
리스트로 노출해 직원이 선택한다. 뒤 4자리는 고유하지 않다.
