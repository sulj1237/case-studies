Problem — 무엇이 문제였나

약국의 단골 관리와 포인트 운영을 동시에 해결해야 했습니다

고객 관계

단골을 챙길 방법이 필요

약국이 단골 고객을 관리하고 다시 방문을 유도할 수단이 부족함

운영 환경

약국마다 운영이 다름

약국마다 운영 방식이 달라 하나의 방식으로 강제하기 어려움

시스템 책임

같은 잔액을 함께 씀

포인트는 금전성 데이터이므로 여러 시스템에서 동일한 잔액을 다루는 기준이 필요함

“약국이 자유롭게 운영할 수 있는 포인트”와 “시스템이 통제해야 하는 포인트”의 경계를 정의하는 것이 핵심 문제였습니다.

Definition — 문제를 어떻게 정의했나

약국CarePharm
맡는 일운영 · 설정 · 고객 관리시스템 제공 · 거래 기준 통제 · 기록 / 확인
지지 않는 것시스템 기준 위반잔액 직접 운영·정산
내용

약국별 독립 포인트 + 공통 거래 기준

Solution 03 — 거래 기준을 공통화

App / Kiosk / POS / Admin이 동일한 포인트 기록과 거래 기준을 사용한다.

Why — 왜 이 해결책이었나

D1

약국별 독립 운영을 선택했습니다

대안

CarePharm 통합 포인트 — 어느 약국에서 쌓든 어디서나 쓸 수 있게

선택

약국마다 따로. 약국끼리 합치거나 옮길 수 없다.

이유

통합으로 가면 포인트를 운영하는 주체가 케어팜이 된다. 그 순간 케어팜이 포인트를 갚을 책임을 지고, 약사법에서 문제가 될 때도 케어팜이 주체가 된다.

포기한 것

여러 약국에서 포인트를 자유롭게 사용하는 편의를 포기했다. 포인트가 흩어지는 대신, 상환 책임과 약사법상 주체를 약국에 둔다.

편의성을 포기하는 대신, 포인트 운영 주체와 책임 범위를 명확하게 했습니다.

D2

CarePharm이 잔액을 직접 수정하지 않도록 했습니다

대안

본사가 포인트를 직접 운영·정산하고 약국은 설정만 고르게

선택

운영은 약국이 하고, 케어팜은 기록 · 표준 양식 · 확인 기능만 제공한다. 본사 관리자 화면에서 잔액을 직접 만지는 기능은 처음부터 넣지 않았다.

이유

본사가 잔액을 고칠 수 있으면 포인트 분쟁이 생겼을 때 최종 책임자가 본사가 된다. 일이 늘어나는 것보다 책임을 어디까지 지느냐가 더 큰 문제였다.

포기한 것

분쟁 발생 시 본사가 즉시 수정해주는 편의를 포기했다. 약국이 잘못 운영해도 기록으로 확인만 하는 대신, 분쟁의 최종 책임이 본사로 넘어오는 것을 막는다.

즉시 수정의 편의보다 운영 주체와 책임 경계를 명확히 하는 것을 우선했습니다.

다섯 접점의 역할

Kiosk

가입하는 곳

전화번호 · 생년월일 · 성별을 받고 약국별 약관에 동의한다.

App

확인하고 인증하는 곳

바코드 하나로 본인 확인이 되고 한 번 찍으면 끝난다.

POS

실제로 처리하는 곳

거래번호로 중복 적립을 막고, 통신이 끊겨도 두 번 처리되지 않게 한다.

Admin

운영 · 확인하는 곳

약국은 운영하고, 본사는 잔액을 만지지 않고 기록으로 확인만 한다.

대표 예외 3개

중복 요청 — 통신이 끊겨 적립 요청이 두 번 갔다면+
거래번호를 보고 중복 적립을 막는다. 요청 횟수가 아니라 거래 단위로 판단한다.
통신 오류 — 결제 요청이 반복되면+
동일 거래의 중복 처리를 막는다. 다시 보내는 것은 정상 동작으로 본다.
잔액 부족 — 거둘 포인트가 모자라면+
포인트 차감 과정에서 정합성을 보호한다. 잔액을 마이너스로 두지 않는다.

실제 키오스크 화면 (로컬 전용)

Learning — 3개

01

기능보다 책임 범위를 먼저 정의했습니다

포인트 기능을 만드는 것보다 누가 운영하고 어디까지 시스템이 책임질 것인지 정하는 일이 먼저라는 것을 경험했습니다.

02

예외는 정책의 일부였습니다

포인트는 금전성 데이터이기 때문에 정상 흐름뿐 아니라 중복·취소·잔액 부족 등 예외 상황까지 포함해 정책을 정의해야 했습니다.

03

다음에는 출시 후 검증까지 연결하겠습니다

이번 프로젝트에서는 정책과 시스템 구조 설계에 집중했다면, 출시 후에는 실제 사용 데이터와 운영 이슈를 통해 정책이 적절했는지 검증할 계획입니다.

Related Evolution

  2. 2

    발견된 Gap

    앱 미설치 회원은 포인트 사용 불가

  3. 3

    QR Point Use

    등록 휴대전화 기반 포인트 사용 확인 경로 설계

Point Reward System (앱 바코드 기반 사용) → 발견된 Gap: 앱 미설치 회원은 포인트 사용 불가 → QR Point Use (등록 휴대전화 기반 사용 확인 경로, 설계 진행 중 · 미출시)

D3의 선택으로 발생한 사용성 Gap을 다음 문제로 정의하고 후속 기능으로 발전시켰습니다.
