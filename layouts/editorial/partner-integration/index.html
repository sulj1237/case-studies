01

OVERVIEW · 파트너몰 연동 개인정보 처리 기준 설계

작성 중

이미 돌아가던 외부 연동에서 빠져 있던 개인정보 처리 기준을 채운다. 가입·주문 흐름은 그대로 유지한다

항목내용
기간2026
담당연동 정책 · 동의 범위 · 흐름 설계 · 검수
진행설계 완료 · 개발 대기

핵심 — 흐름은 유지, 정보가 오가는 조건을 재정의한다

02

PROBLEM · 이미 연결된 서비스, 빠져 있던 개인정보 기준

작성 중

두 서비스는 이미 연동돼 있었고, 동의 · 고지 · 처리 기준만 비어 있던 상태다

근거 — 데이터 이동 전수 확인(가입 · 로그인 · 주문 · 가입정보 전달이다.) 네 곳 모두에서 동의 · 고지 · 처리 기준 누락을 확인한다. 그래서 약국이 자기 정보의 이동을 안내받지 못한 채 연동이 계속 작동한다

가입 경로

경로별 처리 기준 부재

협력도매 · 제약사 VIP · 일반 등 경로마다 회원 구분과 전달 범위가 다르다

개인정보

전달 조건 불명확

무엇을 어디까지 보내는지, 동의는 언제 받았는지 기준 없다

회원

기존·신규 처리 혼재

이미 케어팜 회원인 약국이 약정을 맺을 때 자격 추가 없이 가입 처리한다

03

DECISION · 무엇을 골랐나

작성 중

기존 흐름은 건드리지 않고 조건만 더하는 방향이다. 멈추면 사업이 멈추는 경로였다

01

삭제 대신 유지 + 통제

연동 기능을 걷어내면 약국 업무가 끊긴다. 흐름은 두고 전달 조건을 붙이는 쪽을 택한다

02

동의 상태가 전달을 결정

동의와 실제 전달이 따로 놀던 구조를 바꿔, 동의 기록이 있을 때만 시스템이 정보를 보낸다

03

경로별 회원 구분

협력도매 약정과 일반 메뉴 유입을 다른 값으로 구분해 관리자 화면에서 식별한다

04

HOW · 어떻게 만들었나

작성 중

여섯 질문을 경로 · 전달 · 동의 · 상태 · 기록 다섯 규칙으로 정리한다

규칙내용
가입 경로협력도매 약정 → K제약 VIP · 일반 메뉴 → 일반 K제약
전달 항목정보별 제공 조건과 시점 정의
동의제3자 제공 동의 기록이 있을 때만 전달
진행 상태가입 · 약정 단계별 조건 확인
기록언제 어떤 약관에 동의했는지 보관
  1. 1

    약국

    가입 또는 주문 시작

  2. 2

    시스템

    경로 판별 · 동의 상태 확인

  3. 3

    화면

    필요한 동의를 그 자리에서 수집

  4. 4

    시스템

    조건 충족 시 정보 전달 · 기록 저장

05

RESULT · 무엇이 정해졌나

작성 중

동의 기록이 없으면 정보가 넘어가지 않는다. 약국이 쓰던 흐름은 그대로 두고 조건만 얹었다

기존설계 후
전달 기준기능마다 따로정보별 제공 조건 · 시점 정의
약국 구분구분 기준 필요경로별 VIP · 일반 구분
동의동의와 전달이 분리동의 상태가 전달 여부를 결정
기록확인 불가동의 시점과 약관 버전 보관

다음 고도화 — 연동 항목별 전달 규격과 동의 철회 처리를 더한다. 경로별 가입 건수와 전달 차단 건수로 조건이 실제로 작동하는지 본다

06

NEXT · 한계와 다음 반복

작성 중

규칙은 확정, 남은 것은 시스템 간 상세 규격.
