01

Overview

약국이 약국 단위로 독립 운영하는 포인트 시스템을 신규 설계했다. 다섯 채널이 하나의 원장을 공유한다.

02

Context

약국이 단골 고객을 관리할 수단이 플랫폼에 없었다. 재방문 고객을 알아볼 방법도, 재방문을 유도할 수단도 없었다.

조건 1

다섯 채널에서 일관되게 동작

한 채널에서만 성립하는 규칙은 나머지 네 곳에서 깨진다.

조건 2

약사법 제약 안에 있을 것

적립률을 약국이 자유롭게 정하게 두면 유인행위 리스크가 플랫폼으로 넘어온다.

03

Problem

문제를 세 층으로 나눠 정의했다. 셋을 섞으면 해법이 어긋난다.

비즈니스

고객 관계를 쌓을 도구가 없다

약국에게 케어팜은 결제·조제 도구일 뿐이었다.

고객

자주 가도 쌓이는 게 없다

다른 약국을 가도 잃는 것이 없다.

약국 직원

단골인지 알 방법이 없다

안다 해도 줄 수 있는 것이 없다.

구조

금전적 가치를 갖는 원장

다섯 채널이 같은 잔액을 읽고 쓴다. 이중 적립·차감은 그대로 손실이 된다.

05

Constraint

법률

약사법 — 환자 유인행위

조제약은 적립·사용 제한이 필요하고, 일반의약품은 법무 검토 중이다.

개인정보

수집과 동의 이력

전화번호·생년월일 8자리·성별을 수집하고, 약관·제3자 제공 동의 이력을 남긴다.

책임 구조

운영 책임은 약국에

본사는 직접 부채·잔액을 관리하지 않고, 마이너스 포인트도 부채로 잡지 않는다.

1차 범위

의도적으로 좁힌 영역

부분 취소 · PIN 인증 · QR 제외. 바코드와 보유 포인트 중심.

연동

다섯 채널 데이터 정합

거래번호로 중복 적립을 막고, 통신 실패 시 중복 처리를 차단한다.

06

Policy

포인트 운영

항목정책
운영 단위약국 단위 독립 · 합산·이동 불가
운영 주체 / 시스템약국 / 케어팜
유효기간적립일 기준 5년 · 만료 14일 전 안내
사용 조건단골약국 등록 고객 + 고객앱 바코드 인증
부분 취소1차 범위 미지원

적립 · 사용

항목정책
적립 기준결제금액 − 사용 포인트 = 실제 결제 잔액
조제약적립·사용 제한
일반의약품제한 또는 적립만 허용 (법무 검토 중)
의약외품 · 비의약품허용 가능성이 높은 영역
차감 우선순위유효기간 임박분 우선 (검토 중)

적립 기준을 실결제액으로 잡은 이유는 포인트로 포인트를 낳는 구조를 막기 위해서다. 전액 기준이면 쓸수록 적립이 늘어 원장이 팽창한다.

나머지 정책

취소 · 환불+
전체 취소 시 사용 포인트 복구 · 적립 포인트 회수. 부분 취소는 1차 미지원. 이미 만료된 포인트는 복원되지 않을 수 있고, 회수 불가분은 자동 조정 포인트로 표기한다 (방식 검토 중). 마이너스 잔액은 부채로 관리하지 않는다.
회원 · 동의+
케어팜 회원(앱 가입) / 약국 회원(약국별 약관 동의) / 비회원(적립·사용 제한)으로 나눈다. 가입은 키오스크 중심이며 전화번호·생년월일 8자리·성별을 수집한다. 약국별 약관은 약국이 운영·책임지고 케어팜은 표준 템플릿만 제공한다.
법무 · 규제+
의약품·조제약 포인트 사용을 제한하고, 약국 자율 설정은 본사 공통 기준선 위에서만 허용한다. 케어팜은 운영자가 아닌 시스템 제공자로 역할을 제한하며, 정책 변경·거래·수동 조정 이력을 저장한다.

07

Decision

D1

포인트를 약국 단위로 독립 운영한다

대안

케어팜 통합 포인트 — 어느 약국에서 쌓든 어디서나 쓸 수 있는 구조

선택

약국별 독립 원장. 약국 간 합산·이동 불가.

이유

통합 포인트로 가면 운영 주체가 케어팜이 된다. 그 순간 케어팜이 포인트 부채를 지고 약사법상 유인행위 주체도 케어팜이 된다.

포기한 것

고객 편의. 여러 약국을 쓰는 고객은 포인트가 흩어진다.

D2

케어팜의 역할을 시스템 제공자로 한정한다

대안

본사가 포인트를 직접 운영·정산하고 약국은 정책만 선택

선택

운영 주체는 약국, 케어팜은 원장·정책 템플릿·모니터링만 제공. 슈퍼어드민 초기 범위에서 직접 부채·잔액 관리 기능을 제외했고, 고객 포인트 임의 조정도 제한적으로만 열었다.

이유

본사가 잔액을 조정할 수 있으면 포인트 분쟁의 최종 책임자가 본사가 된다. 운영 부담보다 책임 범위가 더 큰 문제였다.

포기한 것

직접 개입 수단. 약국이 잘못 운영해도 즉시 바로잡을 수 없고 사후 감사로만 확인한다.

D3

포인트 사용 인증을 고객앱 바코드로 고정한다

대안

PIN 인증 · 전화번호 확인 · QR

선택

고객앱 바코드 단일 수단. QR을 제거하고 PIN 인증은 범위에서 뺐다.

이유

전화번호만으로는 타인이 남의 포인트를 쓸 수 있고, PIN은 직원 앞에서 입력해야 해 노출 위험이 있다. 앱 바코드는 로그인 상태가 인증을 대신하며 스캔 한 번으로 끝난다.

포기한 것

앱 미설치 회원은 포인트를 쓸 수 없다. 이 사각지대는 후속 프로젝트에서 별도 경로로 해결했다.

D4

적립 기준을 실제 결제 잔액으로 한다

대안

결제금액 전액 기준

선택

결제금액에서 사용 포인트를 뺀 실결제액 기준. 거래번호로 중복 적립을 차단.

이유

전액 기준이면 포인트를 쓸수록 다시 적립돼 원장이 팽창한다.

D5

1차 범위에서 부분 취소를 지원하지 않는다

대안

부분 취소 시 사용·적립 포인트를 비율로 안분

선택

일괄 취소만 지원.

이유

부분 취소는 라운딩 규칙과 차감 우선순위가 함께 확정돼야 성립한다. 회계 기준이 없는 상태에서 구현하면 원장 정합성이 깨진다.

포기한 것

부분 환불이 잦은 약국의 편의. 전체 취소 후 재결제로 처리된다.

08

UX & System

각 채널은 그 자리에서만 할 수 있는 일을 맡는다.

키오스크

가입의 진입점

약관 동의처럼 시간이 걸리는 절차를 결제 카운터에서 떼어내야 직원 응대가 막히지 않는다.

고객앱

조회와 인증

약국별 포인트를 카드로 보여주고, 사용 시 바코드를 제시한다.

POS

처리

실결제액 기준 적립, 바코드 인증 후 차감, 취소 시 복구·회수를 담당한다.

약국 어드민

운영

이력 조회와 수동 조정. 조정에는 사유와 이력이 필수다.

슈퍼어드민

감사

직접 운영하지 않는다. 현황·이력·액션 로그 조회와 정책 템플릿 관리에 한정.

09

Edge Cases

원장을 다루는 기능이라 예외 처리가 정책의 일부다. 각 항목을 열면 그렇게 정한 근거가 나온다.

통신 실패로 적립 요청이 재전송됨+
거래번호 기준으로 중복 적립을 차단한다. 재시도는 정상 동작이므로 요청 단위가 아니라 거래 단위로 판정해야 한다.
결제 취소 시점에 사용 포인트가 이미 만료+
복원되지 않을 수 있다. 만료는 시간 기준으로 이미 확정된 상태이기 때문이다.
취소했으나 적립분을 회수할 잔액이 부족+
자동 조정 포인트로 표기한다 (표기 방식 검토 중). 잔액을 음수로 두지 않기 위함이다.
잔액이 음수가 되는 상황+
실제 부채로 관리하지 않는다. 케어팜은 시스템 제공자이며 부채 주체가 아니다.
동일 전화번호 뒤 4자리 회원이 복수+
리스트로 노출해 직원이 선택한다. 뒤 4자리는 고유하지 않다.
케어팜 회원이지만 해당 약국 회원이 아님+
약국 회원가입을 유도한다. 약국별 약관 동의가 있어야 그 약국의 포인트 고객이 된다.
앱 미설치 회원이 포인트를 쓰려 함+
적립만 가능하고 사용은 불가하다. D3의 의도된 결과이며, 후속 프로젝트에서 별도 경로를 추가했다.
부분 환불 요청+
1차 범위 미지원. 전체 취소 후 재결제로 처리한다. 라운딩 규칙이 미확정인 상태에서 원장 정합성을 우선했다.
