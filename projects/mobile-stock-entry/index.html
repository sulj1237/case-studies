03 DECISION

작성 중

현장에서 바로 입력할 수 있도록 모바일로 업무를 옮기면서, 입력값·상품 정보·실제 재고의 역할과 반영 기준을 분리했다.

판단해야 했던 문제 → 결정한 방향

고려해야 했던 문제결정
현장에서 입력한 값을 언제 실제 재고에 반영할 것인가?모바일 입력과 실제 재고 반영을 분리한다.
상품 정보와 실재고를 하나의 흐름으로 관리할 것인가?상품 정보와 실재고를 별도 흐름으로 분리한다.
여러 건의 제출값을 PC에서 어떻게 처리할 것인가?PC에서 확인 후 필요한 건을 선택해 반영하는 구조로 한다.
입력한 실재고를 기존 전산 재고와 어떻게 반영할 것인가?현장에서 확인한 수량을 기준으로 실제 재고를 반영한다.
여러 약사가 같은 상품을 중복 입력하면 어떻게 할 것인가?중복 제출을 구분하고 최종 반영값을 선택할 수 있도록 한다.

04 HOW

작성 중

현장에서 입력한 데이터와 실제 재고를 분리하고, 약사앱 → 서버 → PC → 약국 재고로 이어지는 흐름을 설계했다.

앱은 입력·제출, PC는 확인·반영, 슈퍼어드민은 상품 마스터를 관리한다.

상품·실재고 데이터 흐름

  1. 1

    ① 약사앱

    바코드 스캔 → 상품 등록 / 실재고 입력 → 제출

    →
  2. 2

    ② 제출 데이터

    상품 정보 / 진열·창고 수량 → 반영 전 데이터로 저장

    →
  3. 3

    ③ PC 클라이언트

    제출 내용 확인 → 필요한 건 선택 → 실제 재고 반영

    →
  4. 4

    ④ 약국 재고

    PC에서 반영한 총 수량을 실제 전산 재고로 적용

Role Separation · 플랫폼별 역할

약사앱PC 클라이언트슈퍼어드민
현장 입력제출 데이터 확인상품 마스터 관리
상품 등록·수정 제출상품 수정 요청 반영신규 상품 및 수정 이력 관리
진열·창고 수량 입력실재고 최종 반영약국별 제출 로그 관리
제출 이력 확인——

슈퍼어드민에서 실재고를 관리하는 것이 아니다. 실재고는 약국 운영 데이터이며 PC 클라이언트에서 최종 반영된다.

상품 정보와 실재고를 분리

상품 정보실재고

슈퍼어드민: 상품 마스터 관리PC: 확인 → 약국 전산 재고 반영
PC: 필요한 수정 반영—
여러 약국이 공유하는 상품 정보와 변경 이력 관리약국별 실제 보유 수량 관리

예외 상황

중복 제출·네트워크 오류·재고 차이 등 예외 상황에서도 입력값과 실제 재고의 기준이 섞이지 않도록 처리 구조를 분리했다.

여러 약사가 같은 상품을 제출+
바코드로 묶어 1건만 선택 — 최신 기본, 원본 보존
제출 중 네트워크가 끊김+
전체 실패 처리, 제출 목록 유지 — 다시 시도
앱과 PC의 재고 차이+
스냅샷과 현재 재고의 시간 차이 — 최종 재고는 반영 시점 총 수량
기존 전산 재고와 입력값이 동일+
보정 사유 입력란 숨김 — 쓴 사유는 세션 보관

05 RESULT

작성 중

현장에서 입력하고, PC에서 확정하는 재고 관리 구조

PC에서만 입력하던 재고 업무를 현장으로 옮기고, 입력 데이터와 실제 재고를 분리해 관리할 수 있도록 구조를 재설계했다.

재고 확인과 입력을 한 공간에서

BEFOREAFTER
진열대·창고에서 수량 확인 → 기억·메모 → PC 이동 → 재입력상품 앞에서 바코드 스캔 → 진열·창고 수량 입력 → 바로 제출

확인한 재고를 기억하거나 다시 옮겨 적는 과정을 줄였다. 상품 등록도 현장에서 바로 진행할 수 있다.

입력값과 실제 재고를 분리

BEFOREAFTER
PC에서 입력한 값 → 즉시 전산 재고 반영약사앱 입력 → 제출 데이터 → PC 확인 → 실제 재고 반영

앱은 입력하고, PC에서 실제 재고를 확정한다.

재고 데이터를 추적할 수 있도록 구조화

06 NEXT · 운영에서 검증할 것

작성 중

기본 구조는 설계했지만, 실제 운영에서는 제출량과 처리 과정에 대한 검증이 필요하다.

출시 전 확정

항목내용
01 실재고 반영 권한누가 실제 재고를 확정할 수 있는지
02 중복 제출 처리동일 상품의 복수 제출을 어떻게 처리할지
03 반영 실패 처리실패한 제출값의 재처리 기준

출시 후 검증

항목내용
01 제출 → 반영 처리 시간현장 입력 후 실제 재고 반영까지 걸리는 시간
02 중복 제출 빈도동일 상품이 여러 번 제출되는 빈도
03 반영 결과반영완료 · 반영반려 · 반영실패 비율
04 재고 차이현장 조사값과 기존 전산 재고의 차이 발생 빈도

실제 출시 전 프로젝트이므로 ‘개선했다’, ‘감소했다’ 등의 표현을 사용하지 않는다. 출시 후 검증할 지표를 KPI처럼 확정된 성과로 표현하지 않는다.

다음 단계에서는 실제 운영 데이터를 통해 현장 입력부터 재고 반영까지의 처리 과정과 예외 발생 패턴을 검증할 예정이다.
